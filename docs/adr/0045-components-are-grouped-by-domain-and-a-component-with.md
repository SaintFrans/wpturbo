# ADR-045 — Components are grouped by domain, and a component with one caller lives with it

**2026-09-07** · **Status**: Accepted

**Decision** — `resources/js/components/` is grouped into `shell/`, `organizations/`, `clients/`
and `account/` beside `ui/`, `layouts/` is flat, and a component whose only caller is one other
component is folded into that caller rather than given a file of its own.

The flat list had grown to 44 files in one directory, in which `nav-user`, `nav-main`, `nav-tabs`
and `nav-footer` sat next to each other while only one of them was reachable. Grouping is what
makes that visible.

- **`components/shell/`** — the menu bar and what only it uses: `app-header` (which now carries
  the account menu), `app-search`, `nav-tabs`, `app-logo`.
- **`components/organizations/`, `components/clients/`, `components/account/`** — one directory
  per resource domain, holding that domain's modals and cards. A new domain (`servers/`, `sites/`)
  gets its own; it does not get added to the root.
- **The root keeps only what every domain uses**: `alert-error`, `empty-state`, `input-error`,
  `password-input`, `text-link`, `flash-toaster`.
- **`layouts/` is flat and one layout is one file.** `app-layout` absorbed `AppShell` and
  `AppHeaderLayout`, `content-layout` absorbed `AppContent`, `auth-layout` absorbed
  `AuthSimpleLayout`, and `section-layout` moved out of `components/` — it is a layout, and it was
  the only thing in `components/` that arranged a page. The `layouts/app/`, `layouts/auth/`,
  `layouts/settings/` and `layouts/organizations/` subdirectories are gone, and with them
  `layouts/settings/layout.tsx`, which was named after neither what it is nor what it holds
  (it is `account-layout.tsx`).
- **One caller means one file.** `SectionNav` and the sidebar collapse button live inside
  `section-layout`; `UserMenuContent` inside `app-header`; `PasskeyItem` and `PasskeyRegistration`
  inside `manage-passkeys`; `TwoFactorRecoveryCodes` inside `manage-two-factor`; `AppLogoIcon`
  beside `AppLogo`. Each pair could only ever be read together, and splitting them bought a prop
  interface between two halves of one component.
- **The alternative sidebar template is deleted**, not kept for later: `app-sidebar-layout` and
  its `app-sidebar`, `app-sidebar-header`, `nav-main`, `nav-footer`, `nav-user`, `user-info` and
  `breadcrumbs`, plus `auth-card-layout` and `auth-split-layout`. Nothing imported any of them.
  Breadcrumbs went with them — they were declared by four pages and rendered by nothing — and so
  did the `AppShell`/`AppContent` `variant` prop that existed to serve both templates.

**Alternatives**

- **Keep the flat list.** It is fine at fifteen files and unreadable at forty-four. The cost is
  not aesthetic: `nav-user` and `user-info` survived a shell rewrite unnoticed because nothing in
  the directory said which shell they belonged to.
- **Keep the alternative template as a fallback.** `resources/js/CLAUDE.md` had to carry a
  paragraph explaining that adding navigation to those files would not make it appear anywhere.
  Guidance that exists to warn about dead code is a reason to delete the code. Git has it.
- **Split by kind (`modals/`, `cards/`, `nav/`) instead of by domain.** It groups things that
  are never changed together and separates the two files you always open at once.
- **Put the collapse button in `components/ui/sidebar.tsx`.** That is where it belongs by
  subject, but `components/ui/` is regenerated by the shadcn registry, and ADR-044 records what
  that has already destroyed twice. It lives in `section-layout`, which is the only place that
  renders a sidebar.

**Why** — Every component in this app has exactly one shell and, mostly, exactly one caller. A
directory that reflects that makes an orphan visible, which is the failure this cleanup found
three times: an unreachable sidebar template, a `use-flash-toast` hook with no caller (so fifteen
controller actions were flashing toasts nothing rendered), and a registry-added `use-mobile.ts`
shadowing the hand-written `use-mobile.tsx`.

**Consequences**

- A new resource domain gets `components/<domain>/`. Do not add to the root; the root is the
  shared set, and it should stay short enough to read.
- A component extracted "for reuse" that has one caller belongs in that caller until a second
  one appears.
- Breadcrumbs are gone entirely: the `BreadcrumbItem` type, the `breadcrumbs` prop and
  `ui/breadcrumb.tsx`. Reintroducing them means rendering them, not just declaring them.
- `tests/Feature/ShellStructureTest.php` reads the shell's files by path and had to move with
  them; `tests/Feature/FlashToastTest.php` is new, and asserts the notification path is mounted.
